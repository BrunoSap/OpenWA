<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Retention job -> messages table | job deletes rows based on expiresAt/deletedAt timestamps; runs as system context, not API-exposed |
| Config env -> retention window | RETENTION_DAYS_DEFAULT influences which rows expire |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08 | Denial of Service | retention cleanup scan | medium | mitigate | Back the `deletedAt IS NULL` / `expiresAt < now` scan with an index; batch/limit deletes so a large backlog does not lock the hot messages table |
| T-05-09 | Repudiation / Compliance | premature or missed deletion | high | mitigate | Two-stage (soft then hard after grace period); log count + oldest-deleted per run for auditability; cleanup not exposed via API (system-only) |
| T-05-10 | Tampering | retention window override | medium | mitigate | expiresAt computed at insert from validated RETENTION_DAYS_DEFAULT integer; parameterized delete queries only |
</threat_model>
