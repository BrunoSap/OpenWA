<objective>
Tracer slice for the React SPA (Wave 2 track): wire ONE analytics view (Overview) end-to-end
through every layer the phase touches — TypeScript types, API client, real-time hook, page
component, KPI card, route, and sidebar nav — proving the auth + real-time data path works before
expanding to the other views.

Purpose: The riskiest unknown is real-time auth. Native EventSource CANNOT set the X-API-Key
header this dashboard uses (confirmed: api-key.guard.ts extractApiKey reads only X-API-Key header
or Authorization Bearer; there is no cookie/query-param path). Prove the fetch-based SSE reader +
polling fallback works on the happy path first, so an architectural dead-end surfaces after one
commit rather than after five pages are built on a broken stream assumption.
Output: a working, committed Overview page with one live KPI.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Analytics API | React SPA sends X-API-Key with each analytics request; API enforces OPERATOR role |
| SSE stream → Browser | Long-lived fetch stream carries KPI snapshots (may include aggregated business data) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-04 | Elevation of Privilege | /analytics route accessible to non-operator | high | mitigate | API enforces @RequireRole(OPERATOR) server-side (defense in depth); nav gated to operator/admin client-side |
| T-07-05 | Information Disclosure | API key logged in stream/fetch errors | medium | mitigate | Never console.log the key; error handlers log status only (RESEARCH security note) |
| T-07-06 | Tampering | XSS via KPI values in JSX | low | accept | React auto-escapes; values are numbers formatted client-side |
| T-07-07 | Spoofing | SSE over plaintext http in prod | medium | mitigate | Same-origin relative /api path; production served over TLS by NestJS/proxy |
</threat_model>
