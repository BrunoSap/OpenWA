<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public signup endpoint | No authentication required; must prevent abuse (spam signups, email bombing) |
| Admin key exposure | Returned in signup response; client must store securely; never logged or transmitted unencrypted after initial response |
| Onboarding validation | Clients cannot advance steps without validation; server must enforce checks (session ready, message sent) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-16 | Denial of Service | Signup endpoint spam | high | mitigate | Rate limit POST /api/tenants/signup via IP (10 signups/hour per IP); add CAPTCHA (TODO); email verification before activation (TODO) |
| T-09-17 | Information Disclosure | Admin key logged | critical | mitigate | Admin key returned in response but NEVER logged; audit logs mask API keys; response shown once, client must save immediately |
| T-09-18 | Tampering | Client skips onboarding steps | medium | mitigate | Server validates step completion in POST /api/onboarding/:tenantId/advance; client cannot bypass (e.g., cannot advance to 'complete' without session ready) |
| T-09-19 | Spoofing | Email address reuse | medium | accept | No email uniqueness constraint in plan 4; same email can create multiple tenants. Mitigation deferred (email verification + unique constraint in follow-up) |
| T-09-20 | Elevation of Privilege | Admin key has full access | high | mitigate | Admin key role=ADMIN but still tenant-scoped (TenantScopedRepository filters by tenantId); cannot access other tenants' data; @RequireUnscopedKey prevents scoped keys on admin routes |

## Plan 4 Known Gaps (Accepted)

- **No CAPTCHA on signup**: Vulnerable to bot spam. Mitigation: Add CAPTCHA in follow-up (e.g., hCaptcha, Cloudflare Turnstile).
- **No email verification**: Email not validated before tenant activation. Mitigation: Send verification email with token, tenant inactive until verified (follow-up).
- **No email uniqueness**: Same email can create multiple tenants. Mitigation: Add unique constraint + email verification (follow-up).
- **Frontend not in Docker**: React app runs separately via npm run dev. Mitigation: Add frontend build to docker-compose (follow-up).
</threat_model>
