<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API key → Tenant mapping | Untrusted client presents API key; guard must resolve correct tenant without spoofing |
| ClsService → Repository queries | AsyncLocalStorage tenantId must not leak across requests in connection pool |
| Migration backfill | Default LEGACY_TENANT_ID must not cross-contaminate if multiple tenants created before backfill |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Spoofing | API key validation | high | mitigate | API key hashed in DB; guard validates hash before resolving tenant; no client-supplied tenantId accepted |
| T-09-02 | Tampering | ClsService context | medium | mitigate | ClsService is request-scoped (AsyncLocalStorage); each request gets isolated context; verify no shared state |
| T-09-03 | Information Disclosure | Cross-tenant query leak | critical | accept (plan 1 only) | Plan 1 does NOT enforce query filtering; repositories return all rows regardless of tenantId. Mitigation deferred to plan 2 (TenantScopedRepository). Document as known gap. |
| T-09-04 | Elevation of Privilege | Session-scoped key bypasses tenant boundary | high | mitigate | RequireUnscopedKey decorator on tenant admin routes (already enforced by api-key.guard.ts L99-105) |
| T-09-SC | Tampering | npm package legitimacy | high | mitigate | nestjs-cls@4.7.0 verified on npm registry (RESEARCH.md L36), published by official NestJS org, 1M+ weekly downloads |

## Plan 1 Known Gaps (Accepted)

- **No query-level isolation**: SessionService.findAll() returns all sessions, ignoring tenantId. Test documents this as TODO. Mitigation: Plan 2 implements TenantScopedRepository with WHERE tenantId = ? filter.
- **No RLS safety net**: PostgreSQL RLS disabled. If app-level scoping fails, leak is possible. Mitigation: Plan 5 adds RLS as defense-in-depth.
- **API key creation manual**: Test manually inserts api_keys with tenantId. Mitigation: Plan 2 implements TenantService.createApiKey.
</threat_model>
