<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository queries → Database | WHERE tenantId filter must be present in all queries to prevent cross-tenant leaks |
| Redis rate limit counters | Tenant A must not be able to exhaust tenant B's rate limit quota |
| API key creation | Admin creating key for tenant X must not accidentally scope it to tenant Y |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-05 | Information Disclosure | Repository forgot WHERE tenantId | critical | mitigate | TenantScopedRepository base class enforces tenant filter in every query; code review ensures all repositories extend base; E2E tests verify cross-tenant queries return empty |
| T-09-06 | Denial of Service | Rate limit key collision | medium | mitigate | Redis key includes tenantId: `rate_limit:tenant:{tenantId}:...`; no shared counters between tenants |
| T-09-07 | Elevation of Privilege | Admin creates key with wrong tenantId | high | mitigate | TenantService.createApiKey explicitly sets tenantId in CLS context before calling AuthService; no client-supplied tenantId accepted |
| T-09-08 | Denial of Service | Single tenant exhausts Redis memory | medium | accept | Redis eviction policy set to allkeys-lru (configured in docker-compose.yml); rate limit keys have TTL (2x window); monitoring alert if Redis memory >80% |
| T-09-09 | Information Disclosure | findAllTenants bypasses scoping | high | mitigate | findAllTenants method documented as admin-only with code comment; routes calling it must use @RequireRole(ApiKeyRole.ADMIN) decorator; audit log records admin cross-tenant queries |
