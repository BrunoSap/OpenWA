<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → WhatsApp | Survey messages sent to user phone numbers (untrusted delivery) |
| WhatsApp webhook → API | Interactive message responses may be spoofed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-10 | Spoofing | WhatsApp webhook list_reply | medium | mitigate | Verify webhook signature using WhatsApp Hub Verify Token (implement HMAC validation per WhatsApp API docs) |
| T-10-11 | Information Disclosure | Survey messages reveal conversation occurred | low | accept | Surveys sent only to users who initiated conversation (implicit consent) |
| T-10-12 | Denial of Service | Survey spam to same user | medium | mitigate | Rate limit: max 1 survey per user per 7 days (check last survey timestamp before scheduling) |
| T-10-13 | Tampering | Duplicate survey responses | low | mitigate | UNIQUE constraint on (conversation_id, user_id, survey_type) in analytics_satisfaction_responses |
| T-10-14 | Information Disclosure | GET /satisfaction reveals business metrics | medium | mitigate | Require operator role authentication (reuse existing auth guards) |
</threat_model>
