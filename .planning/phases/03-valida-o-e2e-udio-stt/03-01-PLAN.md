**Helper `test/support/stt-transcribe.ts`:**
- Exportar função assíncrona `transcribeOgg(audio: Buffer, opts: { language?: string; model?: string }): Promise<{ text: string; latencyMs: number }>`.
- A função monta um multipart usando o pacote `form-data` (já resolvível no projeto) com os campos: `file` (o buffer, nome `audio.ogg`, contentType `audio/ogg`), `model` (default `whisper-large-v3`), `language` (quando informado, ex.: `pt`), `response_format` `json`.
- POST para `https://api.groq.com/openai/v1/audio/transcriptions` via `globalThis.fetch` (Node 22+ tem fetch nativo), header `Authorization: Bearer ${process.env.GROQ_API_KEY}` mais `form.getHeaders()`.
- Medir latência com `Date.now()` em volta da chamada de rede e retornar `latencyMs`.
- Em erro HTTP (status >= 400) ou ausência de `GROQ_API_KEY`, lançar erro com mensagem clara (o teste decide se pula ou falha) — NÃO engolir o erro aqui; o tratamento de fallback pertence ao Plan 02.
- Exportar também `wordAccuracy(expected: string, actual: string): number` — normaliza (lowercase, remove pontuação, colapsa espaços) e calcula uma métrica simples de acurácia por palavra baseada em distância de edição normalizada em nível de token (1 - editDistanceTokens / max(tokensEsperados, 1)). Retorna valor em [0,1]. Manter puro e determinístico para ser testável isoladamente.

**Nota sobre o .ogg binário:** o executor deve prover o arquivo .ogg PT limpo de ~10s em `test/fixtures/audio/` (áudio de fala clara com transcrição conhecida) e referenciá-lo em `pt-clean-expected.json`.
